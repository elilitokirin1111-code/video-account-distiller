# 产品需求文档：Video Account Distiller

## 1. 产品定位

`video-account-distiller` 是一个面向内容运营、短视频编导、投放团队、MCN、品牌内容团队和个人创作者的 Agent Skill。

它的核心不是“总结一个账号”，而是建立一条可持续迭代的内容研究链路：

> 数据采集 → 数据清洗 → 样本选择 → 视频拆解 → 账号蒸馏 → 规律验证 → 内容评分 → 发布预测 → 数据复盘 → 规则升级

## 2. 核心目标

### 2.1 业务目标

- 将一次账号拆解沉淀为可复用资产。
- 减少分析人员的主观判断和重复劳动。
- 明确“这个账号做了什么”“为什么可能有效”“哪些能复制”“复制到当前账号需要怎么改”。
- 用历史表现反向校准选题、脚本、开头、结构、时长、CTA 和发布时间。
- 支持竞品对标、单账号诊断、矩阵账号研究和内容项目复盘。

### 2.2 产品目标

首版必须完成：

- 账号与视频数据标准化。
- 代表性样本自动选择。
- 单条视频结构化拆解。
- 账号级内容聚类。
- 账号蒸馏报告。
- 对标差距报告。
- 内容评分 Rubric。
- 发布前预测记录。
- 发布后复盘。
- 规则库的证据与置信度管理。

### 2.3 非目标

首版不追求：

- 绕过登录、验证码或平台风控。
- 违反平台服务条款的大规模抓取。
- 保证播放量或承诺爆款。
- 用单条视频推导账号全部规律。
- 自动照搬文案、镜头或受版权保护素材。
- 把不同平台的原始播放量直接横向比较。
- 用黑箱总分替代分析证据。

## 3. 用户角色

### 3.1 内容运营

需求：

- 快速理解竞品账号。
- 找到高表现选题和低表现共性。
- 输出下周选题与拍摄建议。
- 维护复盘数据库。

### 3.2 编导和脚本策划

需求：

- 拆 Hook、冲突、叙事、节奏、信息密度、情绪曲线和 CTA。
- 把规律转成可写脚本模板。
- 对新脚本做发布前检查。

### 3.3 数据分析人员

需求：

- 统一平台口径。
- 处理异常值和小样本。
- 做账号内标准化、分位数和趋势分析。
- 区分相关关系与验证规则。

### 3.4 品牌和 MCN 管理者

需求：

- 横向比较账号矩阵。
- 查看团队内容能力和稳定性。
- 判断内容模式是否可规模化。
- 输出管理层简报。

## 4. 典型用户任务

### 4.1 单账号体检

输入：

- 账号链接或账号导出数据。
- 最近 30～100 条视频数据。
- 可选字幕、评论、封面和视频文件。

输出：

- 账号定位。
- 内容支柱。
- 样本分层。
- 高低表现差异。
- 内容结构聚类。
- 人设、视觉、语言和商业化模型。
- 最大优势、最大短板和下一步动作。

### 4.2 对标账号蒸馏

输入：

- 1～10 个对标账号。
- 本账号数据。
- 目标受众、产品和资源限制。

输出：

- 每个账号的可观察特征。
- 共性模式和差异化模式。
- 可迁移规律。
- 不可迁移因素。
- 适合本账号的改编方案。
- 证据强度和反例。

### 4.3 单视频深度拆解

输入：

- 视频文件或链接。
- 字幕。
- 封面、标题、评论和表现数据。

输出：

- 前 1 秒、3 秒、5 秒 Hook。
- 时间轴结构。
- 镜头、字幕、声音和信息密度。
- 情绪与价值释放节点。
- CTA。
- 制作成本。
- 可复制元素和风险。

### 4.4 发布前评分

输入：

- 选题、标题、脚本、镜头大纲、目标平台和账号。

输出：

- 维度评分。
- 缺失项。
- 风险项。
- 预测区间。
- 修改建议。
- 不允许用确定语气承诺结果。

### 4.5 发布后复盘

输入：

- 发布时间。
- T+1h、T+24h、T+3d、T+7d 数据快照。
- 评论和转化反馈。

输出：

- 预测误差。
- 异常表现解释。
- 规则支持与反例。
- Rubric 权重更新建议。
- 下一轮实验。

## 6. 产品原则

### 6.1 证据优先

每个结论都要附带：

- 数据范围。
- 样本数量。
- 支持样本。
- 反例。
- 置信度。
- 适用范围。
- 最近更新时间。

### 6.2 账号内归一化优先

默认使用账号内部中位数、分位数和 Robust Z-score 判断表现，不直接用不同账号的原始播放量判断优劣。

### 6.3 事实与推断分离

报告必须区分：

- 事实：原始数据或可直接观察内容。
- 统计关联：重复出现的共同变化。
- 假设：可能原因。
- 验证规则：经过多轮数据支持的可执行结论。

### 6.4 不把爆款等于模板

爆款样本必须与常规样本、低表现样本和异常样本对照。

### 6.5 平台差异保留

跨平台统一字段，但不消除平台机制差异。每个平台可有独立指标和分析规则。

### 6.6 数据可追溯

任何报告字段都应能追溯到原始记录或分析运行 ID。

## 7. 输入方式

- CSV。
- JSON / JSONL。
- Excel，可转换为 CSV 或 Parquet。
- 字幕：SRT、VTT、TXT、JSON。
- 视频：MP4、MOV、MKV。
- 图片：封面、关键帧。
- 手工录入。
- 平台 Adapter。
- API 或浏览器导出结果。

## 8. 输出方式

- Markdown 报告。
- JSON 机器结果。
- CSV/Parquet 明细。
- HTML 可视化报告。
- `knowledge-base/` 中的账号、模式、实验和复盘记录。
- 可选 DOCX/PDF 由其他文档 Skill 负责，不放入分析内核。

## 9. 成功指标

### 工程指标

- 标准 Fixture 数据可完整跑通。
- 所有脚本可重复执行。
- 同一输入得到稳定结构结果。
- 核心模块单元测试覆盖率不低于 80%。
- 失败时不破坏原始数据。
- 每次运行生成 manifest、日志和输出索引。

### 分析指标

- 随机抽查 20 条视频，字段提取准确率达到预设阈值。
- 样本选择包含高、中、低表现和近期样本。
- 报告中所有强结论都带证据。
- 不出现“基于 1 条视频认定账号规律”。
- 预测结果保存为区间和置信度，不输出保证性结论。

## 10. 关键风险

- 平台字段含义不同。
- 播放量或互动数据缺失。
- 粉丝量是当前值，不是发布时间值。
- 删除、投流和二次发布影响数据。
- 小样本造成错误规律。
- 字幕识别误差。
- 评论区不代表全部用户。
- 模型容易对内容进行事后合理化。
- 账号爆款可能来自热点、明星、投流或外部事件。
- 视频内容涉及隐私、版权和敏感信息。

所有风险都必须在分析报告中可见。
