# 视频账号拆解与蒸馏方法论

## 1. 总体框架

分析分为六层：

1. 数据层：账号、视频、指标快照、评论、字幕、镜头和封面。
2. 特征层：选题、Hook、结构、节奏、情绪、视觉、人设、CTA。
3. 表现层：播放、互动、增长、转化代理指标和生命周期。
4. 模式层：账号内重复出现的内容模式。
5. 规则层：有证据、适用范围和置信度的可执行结论。
6. 决策层：选题、脚本、制作和发布建议。

## 2. 样本选择

### 2.1 禁止只选爆款

默认样本必须包含：

- 最近样本。
- 高表现样本。
- 中位表现样本。
- 低表现样本。
- 异常样本。
- 每个主要内容支柱的样本。

### 2.2 建议采样规模

轻量分析：

- 账号视频总数少于 30：尽量全量。
- 30～100：选 20～40 条。
- 100～500：选 40～80 条。
- 超过 500：先做全量指标计算，再分层抽样 60～120 条深度分析。

### 2.3 分层规则

至少按以下维度分层：

- 发布时间。
- 内容支柱。
- 视频时长。
- 表现分位。
- 内容形式。
- 是否热点。
- 是否商业内容。
- 是否投流，数据可得时。

### 2.4 表现分层

以账号内部数据为主：

- S：大于等于 P95。
- A：P80～P95。
- B：P40～P80。
- C：P20～P40。
- D：低于 P20。

样本较少时改用中位数倍数和人工标记。

## 3. 指标体系

### 3.1 基础指标

- 播放量。
- 点赞量。
- 评论量。
- 收藏量。
- 分享量。
- 新增粉丝。
- 主页访问。
- 商品点击、私信、线索或成交，数据可得时。
- 完播率、平均观看时长和 3 秒留存，数据可得时。

### 3.2 派生指标

```text
like_rate_by_view = likes / views
comment_rate_by_view = comments / views
share_rate_by_view = shares / views
save_rate_by_view = saves / views
engagement_rate_by_view = (likes + comments + shares + saves) / views
engagement_rate_by_follower = interactions / follower_count_at_publish
follow_conversion_rate = follows_gained / views
profile_conversion_rate = profile_visits / views
completion_efficiency = avg_watch_time / duration_seconds
```

分母为 0 或未知时返回 `null`，不得填 0 冒充真实结果。

### 3.3 Robust 表现分

默认计算账号内 Robust Z-score：

```text
robust_z = (log1p(metric) - median(log1p(metric))) / (1.4826 * MAD)
```

建议综合表现分：

```text
performance_score =
    w_view * robust_z_views
  + w_like * robust_z_like_rate
  + w_comment * robust_z_comment_rate
  + w_share * robust_z_share_rate
  + w_save * robust_z_save_rate
  + w_follow * robust_z_follow_conversion
  + w_watch * robust_z_watch_efficiency
```

权重不能硬编码成唯一真理。应提供平台默认值、账号自定义值和数据缺失时的降级规则。

### 3.4 爆款指数

建议输出两个版本：

- `viral_index_account`：相对本账号历史。
- `viral_index_peer`：相对同平台、同量级、同时间窗口的对标组。

没有可靠同层对标数据时，不生成 `viral_index_peer`。

### 3.5 稳定性指标

账号不能只看最高播放，还要看：

- 中位表现。
- P25 表现。
- P75/P25。
- 高表现命中率。
- 连续低表现长度。
- 内容支柱间方差。
- 发布频率稳定性。
- 高表现模式的复现率。

## 4. 账号蒸馏维度

### 4.1 账号定位

- 目标用户。
- 用户场景。
- 用户问题。
- 提供的价值。
- 差异化。
- 账号承诺。
- 商业化路径。

### 4.2 人设

- 身份标签。
- 专业度。
- 权威来源。
- 亲近感。
- 情绪温度。
- 口头禅。
- 价值观。
- 冲突边界。
- 镜头中的角色关系。

### 4.3 内容支柱

每个支柱记录：

- 名称。
- 用户需求。
- 典型选题。
- 样本数量。
- 表现中位数。
- 高表现率。
- 转化代理指标。
- 制作成本。
- 可持续性。
- 风险。

### 4.4 包装层

- 标题句式。
- 封面信息层级。
- 首帧。
- 主体大小。
- 字幕密度。
- 色彩与构图描述。
- 是否结果前置。
- 是否人物前置。
- 是否使用数字、反常识、冲突、身份或悬念。

### 4.5 视频结构

统一切分：

1. Hook。
2. 建立问题。
3. 承诺价值。
4. 展开或证明。
5. 情绪/信息峰值。
6. 结论。
7. CTA。
8. 循环或尾部承接。

每段记录开始时间、结束时间、功能、文字、镜头和音频特征。

### 4.6 语言

- 句长。
- 语速。
- 信息密度。
- 专有名词比例。
- 口语程度。
- 观点强度。
- 反问。
- 数字。
- 故事。
- 证据。
- 对用户的称呼。
- CTA 用语。

### 4.7 视觉与制作

- 真人口播、剧情、混剪、录屏、产品展示、Vlog、采访等。
- 平均镜头时长。
- 镜头切换密度。
- 景别变化。
- B-roll。
- 字幕样式。
- 动效。
- 音乐。
- 音效。
- 场景。
- 灯光。
- 制作成本等级。
- 是否容易批量生产。

### 4.8 情绪曲线

可使用离散标签：

- 平静。
- 好奇。
- 紧张。
- 冲突。
- 惊讶。
- 共鸣。
- 焦虑。
- 爽感。
- 信任。
- 行动驱动。

输出时间轴，不只输出一个总情绪标签。

### 4.9 CTA 与转化

- 评论型。
- 收藏型。
- 分享型。
- 关注型。
- 私信型。
- 主页型。
- 商品型。
- 社群型。
- 下一集型。
- 无显式 CTA。

要分析 CTA 是否与前文价值一致，不能只判断“有没有”。

## 5. Hook 分类

建议建立可扩展分类，不应锁死：

- 结果前置。
- 反常识。
- 强冲突。
- 痛点直击。
- 身份点名。
- 数字清单。
- 时间压力。
- 损失规避。
- 秘密揭露。
- 失败复盘。
- 前后对比。
- 视觉异常。
- 问题挑战。
- 故事悬念。
- 权威背书。
- 社会证明。
- 争议立场。
- 明确利益。
- 过程展示。
- 直接演示。

每条视频可有主 Hook 和辅助 Hook。

## 6. 选题分类

每条内容至少有：

- 一级内容支柱。
- 二级主题。
- 用户任务。
- 需求阶段。
- 内容目的。
- 热点依赖。
- 生命周期。
- 商业化关联。

需求阶段示例：

- 认知。
- 兴趣。
- 比较。
- 决策。
- 使用。
- 复购。
- 分享。

## 7. 评论区蒸馏

### 7.1 评论标签

- 支持。
- 反对。
- 追问。
- 求教程。
- 求链接。
- 购买意图。
- 经验分享。
- 质疑证据。
- 价格异议。
- 功能异议。
- 身份认同。
- 情绪宣泄。
- 玩梗。
- 无关。
- 疑似机器人或广告。

### 7.2 用户需求输出

每个需求记录：

- 原始评论证据。
- 需求描述。
- 用户场景。
- 强度。
- 出现频次。
- 对应内容。
- 可做选题。
- 可做产品动作。
- 风险。

### 7.3 偏差提醒

- 热门评论不等于多数意见。
- 发布者置顶会改变可见性。
- 平台排序可能强化争议。
- 评论用户不是全部观看用户。
- 删除评论会造成样本偏差。

## 8. 模式发现

### 8.1 模式对象

一个 Pattern 应包含：

- `pattern_id`
- 名称。
- 描述。
- 特征组合。
- 支持视频。
- 反例视频。
- 支持样本数。
- 适用内容支柱。
- 适用平台。
- 适用账号阶段。
- 表现提升估计。
- 置信度。
- 可复制成本。
- 风险。
- 最近验证时间。

### 8.2 模式类型

- 选题模式。
- Hook 模式。
- 结构模式。
- 视觉模式。
- 人设模式。
- CTA 模式。
- 发布时间模式。
- 评论触发模式。
- 转化模式。
- 失败模式。

### 8.3 发现方法

第一阶段可使用：

- 分组统计。
- 分位数对比。
- 频次。
- 交叉表。
- 非参数相关分析。
- 决策树解释模型。
- 文本 Embedding 聚类。
- 人工可读标签聚类。

禁止把聚类编号直接当成业务规律。聚类后必须生成可解释描述，并由证据样本支撑。

## 9. 规则成熟度

每条结论属于以下状态之一：

### Level 0：观察

“高表现样本中有 4 条使用结果前置。”

### Level 1：相关性

“结果前置 Hook 的视频在本样本中分享率中位数更高。”

### Level 2：假设

“结果前置可能降低理解成本，从而提高早期留存。”

### Level 3：实验规则

“下一轮在同一内容支柱中进行结果前置与问题前置的对照实验。”

### Level 4：验证规则

“在至少 3 轮、每轮有足够样本的同类内容中，结果前置持续提高目标指标。”

只有 Level 4 可进入默认 Rubric 高权重。

## 10. 账号蒸馏报告结构

1. 执行摘要。
2. 数据范围和质量。
3. 账号定位。
4. 受众和需求。
5. 内容支柱。
6. 表现分布。
7. 高、中、低表现对照。
8. Hook。
9. 结构和节奏。
10. 人设与语言。
11. 视觉与制作。
12. CTA 和商业化。
13. 评论区需求。
14. 爆款模式。
15. 失败模式。
16. 可复制因素。
17. 不可复制因素。
18. 规则和置信度。
19. 30 天内容实验计划。
20. 附录与证据索引。

## 11. 对标迁移矩阵

每个对标规律必须判断：

| 维度 | 问题 |
|---|---|
| 用户一致性 | 对标账号用户与本账号用户是否相近 |
| 价值一致性 | 用户观看动机是否相近 |
| 账号阶段 | 新号、成长期、成熟期是否相同 |
| 资源一致性 | 主播、场景、预算和团队是否可获得 |
| 平台一致性 | 推荐机制与内容消费方式是否相同 |
| 商业一致性 | 转化目标是否一致 |
| 风险 | 是否涉及版权、肖像、医疗、金融或夸大承诺 |
| 可复制度 | 能复制结构还是只能复制表面形式 |
| 改编动作 | 应保留什么、替换什么、删除什么 |

最终标签：

- 直接可试。
- 改编后可试。
- 仅用于理解。
- 不建议迁移。

## 12. 发布前评分 Rubric

建议 100 分，但报告必须展示分项，不只展示总分。

- 账号匹配：15。
- 用户需求：15。
- 选题强度：15。
- Hook：15。
- 结构与价值释放：15。
- 可信度与证据：10。
- 互动与 CTA：5。
- 制作可行性：5。
- 风险控制：5。

权重由已验证规则调整。低置信度规则不得显著改变总分。

## 13. 预测

输出：

- 目标指标。
- P25、P50、P75 预测区间。
- 置信度。
- 主要正向因素。
- 主要负向因素。
- 关键不确定因素。
- 与账号基线的比较。
- 预测时间。
- 模型或规则版本。

禁止输出“必爆”“预计播放量一定达到”等表述。

## 14. 复盘

复盘必须回答：

1. 实际结果相对账号基线如何。
2. 哪些预测正确。
3. 哪些预测错误。
4. 错误来自数据、内容、平台、热点还是外部因素。
5. 哪条规则得到支持。
6. 哪条规则出现反例。
7. 是否更新权重。
8. 下一轮如何验证。
