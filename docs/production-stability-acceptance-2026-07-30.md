# 生产稳定性验收记录（2026-07-30）

## 范围与结论

本轮完成 TikHub 响应漂移诊断、MediaCrawler 环境诊断、持久任务恢复演练，以及工作台主路径的
真实浏览器验收。所有浏览器操作均连接本地 API/Web；采集入口只执行 `dry_run=true` 的预检，
没有调用真实 TikHub 或 MediaCrawler。

本轮提高了生产可观测性和恢复可信度，但不替代真实授权账号、真实 Provider、第二次账号快照、
真实 OpenKB 和创作者后台导出样本的最终验收。

最终质量门禁为 240 项测试通过、覆盖率 85.41%，Ruff、Ruff format、mypy 和
`git diff --check` 均通过。

## TikHub 响应漂移

- 每次 TikHub 采集完成后，对解析、账号、作品和评论响应的映射关键路径做合同检查。
- 新增字段保持兼容；关键字段缺失、类型不兼容或响应结构无法映射时形成错误级漂移。
- 在 Provider 原始批次旁保存不可变的 `drift-report.json`。
- 报告只保存路径、期望类型、实际类型、问题码和无值结构指纹，不保存 Token、请求头或响应值。
- 任务结果使用 `tikhub_response_contract_drift` 或
  `tikhub_response_contract_drift_warning` 暴露状态。

## MediaCrawler 诊断矩阵

doctor 现在统一报告：

- 期望与实际上游 Git 提交以及是否匹配；
- `pyproject.toml` 的 Python 约束、锁文件和许可证；
- 关键入口文件、`uv`、Distiller 桥接脚本；
- Chrome/Edge 通道和解析后的浏览器可执行文件；
- 用户数据目录是否存在；
- `profile_missing` 或 `profile_present_unverified` 登录状态。

诊断不会检查 Cookie、导出会话或仅凭目录存在声称“已登录”。只有授权账号的真实启动与采集
才能完成登录验收。

## 隔离任务恢复演练

`POST /api/doctor/task-recovery-drill` 会在临时目录创建独立 SQLite 任务队列并依次验证：

1. 任务入队、认领和检查点持久化；
2. 租约过期后的中断恢复；
3. 原任务以 `E_TASK_INTERRUPTED` 进入可重试失败；
4. 重试任务继承检查点和 `retried_from`；
5. 重试任务重新认领并完成；
6. 临时数据库退出后已删除。

演练不读取或改写配置中的生产任务数据库。命令行示例：

```bash
curl -X POST http://127.0.0.1:8000/api/doctor/task-recovery-drill
```

同时修正了持久任务重试路径：重试执行器现在会把已保存检查点作为 `resume_state` 传回任务。
