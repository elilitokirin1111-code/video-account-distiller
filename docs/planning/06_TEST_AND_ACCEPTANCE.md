# 测试与验收计划

## 1. 测试原则

- 不只测试代码是否运行，还测试分析结论是否遵守规则。
- 所有核心功能必须有离线 Fixture。
- 模型调用必须可 Mock。
- Golden Test 检查输出结构，不要求自然语言逐字一致。
- 原始数据不可变。
- 失败任务可恢复。

## 2. 测试层级

### 2.1 单元测试

覆盖：

- 字段映射。
- 日期解析。
- 缺失值。
- 去重。
- 指标公式。
- Robust Z-score。
- 分位数。
- 样本分层。
- ID 生成。
- Schema 校验。
- 证据计数。
- 规则成熟度升级。
- 预测不可变。
- 日志脱敏。

### 2.2 合同测试

针对：

- Adapter。
- Model Provider。
- Transcript Provider。
- Report Renderer。
- Knowledge Store。

### 2.3 集成测试

场景：

1. CSV → 标准化 → 指标 → 样本 → 报告。
2. 视频数据 + 字幕 → 单视频拆解。
3. 评论 → 意图 → 需求报告。
4. 多账号 → 对标报告。
5. 脚本 → 评分 → 预测 → 发布 → 复盘。
6. 数据更新 → 增量运行。
7. 模型不可用 → 确定性降级。

### 2.4 Golden 测试

建立固定小数据集：

- 30 条视频。
- 3 个内容支柱。
- 5 条高表现。
- 5 条低表现。
- 2 条异常热点。
- 1 条投流。
- 300 条评论。
- 10 条字幕。

预期验证：

- 样本覆盖所有分层。
- 异常热点不会自动生成高置信度规则。
- 投流视频被标记。
- 低表现样本进入分析。
- 报告包含数据质量说明。
- Pattern 包含反例。

## 3. 分析质量测试

### 3.1 盲分析测试

单视频内容标注时先隐藏表现数据。

验收：

- 标注结果不包含播放、点赞等信息。
- 第二阶段才进行表现解释。
- 结果中保留盲分析版本。

### 3.2 反例测试

输入一个看似符合高表现模式但实际低表现的视频。

验收：

- 系统将其列入反例。
- 规则置信度下降或范围收窄。
- 不删除反例。

### 3.3 小样本测试

只有 3 条视频。

验收：

- 报告明确提示样本不足。
- 不生成验证规则。
- 只输出观察和假设。
- 预测置信度为低。

### 3.4 跨平台测试

输入 TikTok 和 YouTube 视频。

验收：

- 不直接比较原始播放量。
- 分别建立平台基线。
- 只比较归一化结果或可比内容特征。
- 报告提示平台差异。

### 3.5 缺失数据测试

缺少分享、收藏和粉丝量。

验收：

- 对应指标为 null。
- 综合分权重自动重分配并记录。
- 不把缺失值当 0。
- 报告列出缺失项。

## 4. 安全与合规测试

- API Key 不出现在日志。
- 用户名默认脱敏。
- 云模型禁用时不上传内容。
- 删除命令要求确认。
- 未授权 Adapter 返回明确错误。
- 速率限制自动退避。
- 原始数据目录不被报告生成器改写。

## 5. CLI 验收

每个命令：

- `--help` 正常。
- `--json` 输出合法 JSON。
- 失败返回非 0 code。
- stderr 与 stdout 分离。
- 具有稳定错误码。
- 支持 `--dry-run` 的命令不产生修改。
- 重复执行保持幂等，或明确创建新版本。

## 6. Skill 验收

- `SKILL.md` Frontmatter 合法。
- name 与目录名一致。
- description 明确包含使用场景。
- 主文件不超过 500 行。
- 引用路径有效。
- 不存在深层循环引用。
- 脚本有帮助信息。
- `skills-ref validate` 通过。
- Codex 能根据自然语言正确激活。
- “分析账号”不会误触发“登记发布”。

## 7. P0 验收清单

### 项目初始化

- [ ] 创建标准项目目录。
- [ ] 创建配置和数据模板。
- [ ] 不覆盖已有文件。
- [ ] 输出状态。

### 数据导入

- [ ] 支持 CSV/JSON。
- [ ] 保存原始文件。
- [ ] 生成哈希。
- [ ] 字段映射可配置。
- [ ] 输出质量报告。

### 指标

- [ ] 正确处理 0 和 null。
- [ ] 账号内分位数正确。
- [ ] Robust Z-score 有测试。
- [ ] 平台不可比提示。

### 样本

- [ ] 包含高、中、低表现。
- [ ] 包含近期样本。
- [ ] 覆盖主要内容支柱。
- [ ] 输出样本清单和原因。

### 视频分析

- [ ] 输出 Hook、结构、CTA、情绪和证据。
- [ ] 先盲分析。
- [ ] Schema 校验。
- [ ] 低置信度标记。

### 账号蒸馏

- [ ] 输出定位、支柱、人设、内容模式和失败模式。
- [ ] 每个强结论带样本。
- [ ] 包含反例。
- [ ] 包含可复制和不可复制因素。
- [ ] 包含行动建议。

### 评分与预测

- [ ] Rubric 可版本化。
- [ ] 分项可解释。
- [ ] 预测是区间。
- [ ] 预测不可变。
- [ ] 不承诺结果。

### 复盘

- [ ] 比较实际和预测。
- [ ] 更新证据。
- [ ] 保留反例。
- [ ] 生成下一轮实验。
- [ ] Rubric 变更默认待审批。

## 8. Definition of Done

一个里程碑只有同时满足以下条件才算完成：

1. 功能实现。
2. 单元测试。
3. 集成测试。
4. 文档。
5. 示例。
6. 错误处理。
7. 数据迁移说明。
8. 运行结果证据。
9. `git status` 干净。
10. 提交信息清楚。
