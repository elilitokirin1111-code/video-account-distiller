# 视频账号蒸馏器 Windows 桌面版使用说明

桌面版是原生 Qt/PySide6 应用，不依赖浏览器，也不是网页套壳。它在当前 Windows 用户会话中
启动内嵌 FastAPI 与持久任务队列，直接复用命令行和 Web 版的数据模型、工作流与项目目录。

## 安装与启动

- 安装版：运行 `VideoAccountDistiller-Setup-1.0.0-win64.exe`，从开始菜单启动。
- 便携版：解压完整 ZIP 后运行 `VideoAccountDistiller.exe`，不要只复制单个 EXE。
- 源码版：双击仓库根目录的 `启动蒸馏应用.cmd`。

首次启动时应用会自动选择空闲的本机回环端口并启动任务服务。关闭主窗口后，由桌面版启动的
内嵌 API 和 Ollama 子进程会随之停止；应用不会结束原本就由用户启动的 Ollama 或 WeKnora。

## 从主页到逐视频知识文档

1. 在“总览”选择一个目录并点击“初始化项目”。项目数据始终落在该目录。
2. 在“账号蒸馏”粘贴抖音主页链接，选择采集方式、作品范围和媒体处理数量。
3. 选择“视频内容知识提取”，按需设置 Whisper、本地视觉模型与知识模型。
4. 先点“仅预检”，确认范围与依赖，再点“开始蒸馏”。
5. 在“任务中心”查看阶段、进度、错误详情；失败或取消的持久任务可直接重试。
6. 在“知识结果”查看批次，打开目录或导出 ZIP。每条成功视频对应一个以视频标题命名的
   Markdown，Windows 非法字符、保留名、重名和过长名称会安全处理。
7. 如需上传，在“WeKnora”保存本机服务地址和密钥、读取知识库、选中批次账号后同步。

“创作学习/运营蒸馏”是另一条模式：它输出账号诊断、Pattern、策略和报告；“视频内容知识
提取”只提取视频中的陈述、观点、概念、方法、案例和数据，不执行外部事实核验，也不会混入
账号运营结论。两类产物与 WeKnora 文档类型彼此隔离。

## 采集方式与首次准备

- TikHub：把密钥保存在“设置”页，密钥进入 Windows 凭据管理器，不写入项目或任务库。
- MediaCrawler：安装包带有固定版本源码、锁文件、受控桥接器和 `uv`。首次真实采集需要联网
  创建它自己的锁定 Python 环境，并需要本机 Chrome 或 Edge。浏览器会保持可见，登录、验证
  由用户手动完成；应用不做验证码处理、自动登录、隐身或风控绕过。

本地媒体增强仍需要系统可执行程序：FFmpeg/FFprobe；Whisper 需要所选本地后端及模型；视觉
分析需要 Ollama 和已下载的视觉模型。总览页会显示服务可用性，缺失依赖会给出可重试错误，
不会把失败伪装为成功。

## 密钥与隐私

- TikHub、WeKnora、OpenAI、百炼、DeepSeek 密钥保存在当前 Windows 用户的凭据管理器。
- 非敏感偏好保存在 `%LOCALAPPDATA%\VideoAccountDistiller\settings.json`。
- 持久任务保存在 `%USERPROFILE%\.video-account-distiller\api\tasks.sqlite3`。
- 桌面提交的任务只携带凭据提供商引用；密钥不会进入 `distiller.yaml`、任务 payload、结果、
  checkpoint、日志、导出 ZIP 或 Git。
- 选择云端模型会把必要文本或图片发送到所选服务；只有本地模型路径保持媒体离线。

## 常见问题

- “本地服务启动失败”：通常是安全软件拦截回环端口；允许程序访问本机网络后重试。
- “MediaCrawler runtime is not ready”：确认首次初始化网络可用，且 Chrome/Edge 已安装。
- “需要登录”：保持弹出的浏览器窗口可见，完成登录后重试原任务。
- “FFmpeg/Whisper/Ollama 不可用”：安装对应本地依赖或把媒体处理数量设为 0，再重试。
- “云端 401”：确认模型、endpoint 与密钥属于同一个提供商；在设置页重新验证并保存。
- “WeKnora 同步失败”：确认服务地址、文档型知识库 ID 与密钥；批次不完整时应用会拒绝同步，
  防止产生看似完整但实际缺文档的知识库。

任务失败不会删除已采集的原始证据。账号媒体只有在分析产物已经持久化并校验成功后才清理；
关闭应用后再次打开同一个项目，可从任务中心继续查看或重试。
