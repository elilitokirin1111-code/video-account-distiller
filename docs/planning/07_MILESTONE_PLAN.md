# 实施计划与优先级

## 总体策略

先完成离线、可验证的分析内核，再接入在线采集和多模态。不要在第一阶段把主要时间花在平台登录、反爬和浏览器自动化上。

## Phase 0：仓库和工程基线

交付：

- 仓库结构。
- `AGENTS.md`。
- `pyproject.toml`。
- CLI 空壳。
- Pydantic 模型基础。
- 测试框架。
- CI。
- Skill 骨架。
- `skills-ref validate`。

退出条件：

- 安装成功。
- `distiller --help` 可用。
- Ruff、mypy、pytest 通过。
- Skill 能被 Codex识别。

## Phase 1：数据内核

交付：

- CSV/JSON Adapter。
- 字段映射。
- 原始数据存储。
- 标准化 Parquet。
- 数据质量报告。
- DuckDB 查询层。
- 基础指标和 Robust 指标。
- 项目状态。

退出条件：

- 10 万条 Fixture 可导入。
- 重复运行不重复写脏数据。
- 缺失值和时区测试通过。

## Phase 2：样本和报告

交付：

- 分层采样。
- 账号基础统计。
- 账号体检报告。
- 高中低表现对照。
- 数据证据索引。
- Markdown/JSON 输出。

退出条件：

- 样本覆盖规则通过 Golden Test。
- 报告中所有数据可追溯。

## Phase 3：文本级视频分析

交付：

- 字幕导入。
- 视频事实抽取 Prompt。
- 语义标注 Prompt。
- Hook、结构、CTA、情绪和内容支柱 Schema。
- 盲分析两阶段流程。
- 单视频报告。

退出条件：

- 模型输出 Schema 失败可自动重试或降级。
- 盲分析测试通过。
- 低样本不生成强结论。

## Phase 4：评论和账号蒸馏

交付：

- 评论清洗和脱敏。
- 意图、痛点、反对意见和需求聚类。
- 内容聚类。
- Pattern 和 Evidence。
- 反例审查。
- 账号蒸馏报告。
- 对标迁移矩阵。

退出条件：

- 每个 Pattern 有支持样本和反例字段。
- 不同平台使用独立基线。
- 报告可直接用于选题和脚本规划。

## Phase 5：评分、预测和复盘闭环

交付：

- Rubric。
- 脚本评分。
- 不可变预测。
- 发布登记。
- 数据快照。
- 预测误差。
- Retro。
- 规则升级建议。

退出条件：

- 预测不可修改。
- 规则变更有版本。
- 复盘能生成下一轮实验。

## Phase 6：多模态增强

交付：

- Local Media Adapter。
- FFmpeg 元数据。
- 场景切分。
- 关键帧。
- 音频特征。
- OCR/视觉模型 Provider。
- 镜头时间轴。

退出条件：

- 没有 FFmpeg 时可优雅降级。
- 本地模式不上传媒体。
- 多模态结果有时间戳证据。

## Phase 7：平台与协作 Adapter

交付：

- 经授权的平台 API 或导出 Adapter。
- 飞书多维表格导入导出。
- Google Sheets 导入导出。
- 批量任务。
- 定时快照接口。
- 团队配置。

退出条件：

- 每个 Adapter 有独立合同测试。
- 速率限制和权限错误可处理。
- 核心分析不依赖任何单个平台。

## 优先级建议

### 第一轮 Codex 任务

只做 Phase 0 + Phase 1。

### 第二轮

Phase 2。

### 第三轮

Phase 3。

### 第四轮

Phase 4。

### 第五轮

Phase 5。

多模态和在线平台 Adapter 在闭环稳定后再做。

## 并行工作拆分

Codex 多 Agent 可拆为：

- Agent A：数据模型和导入。
- Agent B：指标和采样。
- Agent C：Skill、CLI 和文档。
- Agent D：报告系统。
- Agent E：测试 Fixture 和 Golden Test。

合并前由一个集成 Agent 统一：

- Schema。
- 命名。
- CLI 参数。
- 错误码。
- 版本号。
- 测试。

## 主要技术债务警戒线

- 不允许把模型输出直接写数据库而不校验。
- 不允许平台字段散落在业务代码中。
- 不允许分析报告直接读取原始 CSV。
- 不允许硬编码唯一指标权重。
- 不允许用 Markdown 作为唯一机器存储。
- 不允许规则没有版本。
- 不允许预测可以覆盖。
- 不允许测试依赖真实在线平台。
